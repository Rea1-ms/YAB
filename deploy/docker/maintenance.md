# 容器维护说明

这里记录容器适配时确认的做法和验证范围。安装、启动和设备连接见 [部署说明](README_CN.md)。

## 先区分构建和运行

网页、依赖和识别资源在镜像构建时准备。运行时只启动服务，不能再沿用旧脚本里的代码拉取、强制重置和依赖安装，否则运行内容会偏离构建时的版本。

构建上下文是项目根目录，文件仍保存在 `deploy/docker`（容器部署目录），不需要复制到根目录。`.dockerignore`（构建排除规则）只允许应用和构建输入，并排除本机配置、虚拟环境、网页产物、识别嵌入仓库和敏感文件。前端在独立阶段按锁文件构建，运行镜像不需要前端工具。

`distribution.json`（预置资源标记）让网页和识别程序使用镜像内的资源，避免启动时重新构建或联网更新。修改这种资源处理方式时，同时核对源码启动、桌面发行和容器，不要将一种平台的程序名用于全部平台。

## 依赖与识别程序

后端从 `uv.lock`（依赖锁文件）导出依赖，再用 `uv pip sync`（依赖同步命令）安装到镜像内新建的环境，并校验包摘要。不要复制开发环境，也不要退回维护另一份未锁定的容器依赖清单。

这次使用的 uv 0.13.6（依赖管理工具版本）中，`uv sync`（项目同步命令）不接受构建约束文件参数；应先导出，再使用 `uv pip sync --build-constraints`（带构建约束的依赖同步命令）。旧安卓依赖仍需要 `pkg_resources`（旧版包元数据接口），隔离构建沿用 setuptools 69.5.1（构建依赖）和 wheel 0.45.1（包构建依赖）的约束。

上游预编译识别程序目前只提供 Linux x86_64（常见电脑的 64 位架构）版本。镜像固定识别资源提交，更新时核对程序、配套动态库和模型，再修改构建参数；不能只替换主程序或据此宣称支持其他架构。

离线资源检查按实际平台使用程序名：Windows（视窗系统）带 `.exe`（可执行文件后缀），Linux（服务器系统）不带。构建还会检查后端导入、网页资源和识别程序的动态库依赖；这些检查不能代替真正启动识别程序。

## 数据和设备网络

任务配置、识别设置、识别日志和设备授权分别保存在命名数据卷中。运行镜像使用普通用户，目录需要允许该用户写入；重新构建时保留卷，不挂载整个源码目录覆盖镜像内容。旧版项目目录不会自动迁移到新数据卷。

容器通过网络调试连接使用安卓设备。容器内的 `127.0.0.1`（本机回环地址）指向容器自身，不能直接沿用宿主机上的模拟器回环地址。宿主机映射只提供访问名称，实际调试端口仍须允许容器连接。

宿主机端口和容器内监听分开处理：编排配置决定宿主机访问地址与映射端口，服务内部固定监听 22267 端口。网页密码只通过环境变量传入，不写入镜像、编排文件或项目配置。调度时间使用明确设置的时区。

## 健康检查和验证范围

健康检查携带运行时密码请求真实健康接口，同时确认网页可响应、识别初始化成功且没有识别错误。接口返回成功但识别未就绪时，容器仍应显示未就绪。启动脚本需要校验密码，并将退出信号和命令参数直接交给服务进程；脚本换行固定为 LF（换行格式），避免从 Windows（视窗系统）检出后无法启动。
