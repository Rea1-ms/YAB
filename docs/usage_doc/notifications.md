# 推送通知

在「设置 → 推送通知」添加渠道，选择类型后填写对应参数，再点击「保存推送设置」。可以添加多个渠道，也可以添加同一类型的不同接收方。每个渠道都可以单独停用。

可以选择「本机系统通知」，也可以使用 OnePush（多渠道推送库）1.10.0 提供的电报、飞书、企业微信、钉钉、电子邮件等 18 种远程渠道。远程渠道的可选参数放在「更多参数」中，以 JSON（结构化数据）对象填写；标题和正文由任务自动提供。

「发送测试通知」会使用当前表单里的参数，真实发送一条测试消息，不会保存表单，也不受「出错时推送」「完成后推送」开关限制。正常任务发送仍按这两个开关执行。

已有的方糖、飞书、企业微信、电报和通用接口配置会自动转换为渠道列表，代理和自定义接口地址也会沿用。旧字段保留原值，但转换后以新列表为准；移除全部渠道后不会从旧字段重新启用。

设置保存后，正在运行的配置需要停止后重新启动。测试通知直接使用当前表单，不需要重启。

「完成后推送」包括一轮日常任务结束，以及「剧情推进」「活动一键执行」中的单次任务执行完成。单次任务的通知会写明配置名和执行内容；手动停止、执行失败或没有返回成功，都不会发送完成通知。任务异常和重启恢复失败沿用「出错时推送」；初始化失败及服务自身异常仍主要记录日志。

## 本机系统通知

添加渠道后选择「本机系统通知」，无需填写账号、密钥或代理；保存并开启「完成后推送」或「出错时推送」即可接收对应通知，也可以与远程渠道同时使用。系统通知沿用 YAB（应用名称）作为来源。

通知使用 Windows（视窗系统）原生能力，显示在运行脚本的电脑上。无需申请浏览器通知权限，关闭网页或进入桌面轻量模式后，后台仍可发送；从其他电脑访问网页时，通知也会显示在运行脚本的那台电脑上。其他系统或缺少通知组件时，发送会明确提示不可用。系统勿扰或关闭应用通知可能阻止横幅显示，「已提交系统通知」表示请求已交给系统。

当前版本不会因为脚本报错或手动停止就默认弹出“任务已停止”。脚本报错需要添加并启用通知渠道，再开启「出错时推送」。关机前的取消交互和桌面收起到托盘的提醒，仍使用各自的系统通知，不受任务推送开关控制。

源码更新后需要完整退出并重启应用，才会使用新通知来源；通知中心已有的旧消息不会自动改名。使用旧安装包时，仅更新源码也不会改变包内通知代码，需要换用包含修改的新包。

## 电报

填写机器人的访问令牌和接收会话编号。网络需要代理时，在「代理地址」中填写本机代理地址。

需要自定义接口地址时，在「更多参数」填写：

```json
{"api_url": "https://telegram.example.com"}
```

## 自定义接口

选择「自定义接口」后填写服务地址。默认发送包含 `title`（标题）和 `desp`（正文）的表单数据；旧版通用接口迁移后仍发送原来的 JSON（结构化数据）格式。

在「更多参数」可设置 `method`（请求方法）、`datatype`（数据格式）和 `data`（请求内容）。请求内容支持 `{{title}}`（标题占位符）和 `{{content}}`（正文占位符），也支持嵌套的对象和数组。

## 发送结果

网络连接和响应读取均设置 10 秒超时，发送失败只记录结果，继续处理其他渠道。日志不输出凭据、完整请求地址或服务返回正文。电子邮件发送同样设置连接和读写超时。
