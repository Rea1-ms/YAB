# 离线截图回归

先把遇到过的问题留下来。之后修识别或流程时，使用同一批截图复查，逐步增加场景。

当前入口只运行明确登记的测试，不会自动搜索历史测试，也不会连接模拟器或读取账号配置。已有普通、困难推图测试需要真实设备，仍单独手动运行。

## 目前覆盖什么

| 测试集 | 已有场景 |
| --- | --- |
| `popups`（弹窗） | 进游戏前的活动提示、公告、应用商店未登录提示、国际服新版商店的免费体力领取与中断处理，以及英文资源下载确认。 |
| `recognition`（任务识别） | 模拟检查体力读数校验，以及课程好感度和可选状态的采样。 |
| `activity`（活动） | 真琴夏日活动的入口、双标签切换、故事与任务边界、扫荡配置及无挑战时跳过。 |
| `shop`（商店） | 商品漏识别、固定列编号、缺项恢复、滑动无进展与勾选失败的有限重试。 |
| `drill`（联合火力演习） | 国服快速战斗和扫荡确认弹窗的标题识别。 |
| `version`（版本来源） | 二开版本、旧启动器配置、原仓库基准及无版本库的发行包元信息。 |
| `screenshot`（截图） | 模拟器主页的颜色、原始截图解码、尺寸变化、失败重试和超时恢复。 |
| `infrastructure`（测试基础） | 样本缺失或损坏、真实设备隔离、错误退出状态、失败附件及任务停止和报错处理。 |

这批以已有裁剪截图为主。活动提示另有五张完整脱敏截图；主页标记、部分商店扫描结果及前后帧是明确模拟的输入，不是实机连续操作记录。三种国际服素材语言与多种缩放在弹窗测试内循环检查，不另算独立用例。

## 活动提示的判定约定

进游戏前的活动提示和公告使用不同的特征。活动提示检测左下角两种“不再显示”图标中的任意一种，命中后点击右上角关闭位置；不再把右上角叉号作为匹配条件。以 1280×720 为基准，关闭位置为（1173，75），实际点击继续由已有缩放逻辑转换。

公告仍需同时命中左侧工具栏和自己的关闭特征，关闭位置为（1214，43）。工具栏分别保留公告列表和详情页两种选中状态。不要把活动提示改动套到公告，也不要用主页“小房子”图标判断进游戏前的提示。

新增同类问题时，先补完整脱敏截图，再检查各语言与缩放下的识别和点击；流程回放另放入重复画面、点击未生效及真正结束的画面。点击发生不能代替结束画面的确认。既有国服标题样本只是接入同一回归入口，不代表本轮修改了国服扫荡业务。

## 模拟器主页截图与失败处理

使用 `--suite screenshot`（截图组）运行这组回归。排查模拟器连接错误时，先保留实际返回码和截图方式；完整退出任务后，可把截图与控制都切到 adb（安卓调试连接）作对照。截图读取失败必须在识别前停止，不能用旧画面或空图继续点击。

## 怎么运行

在仓库根目录使用已有虚拟环境。以下依次为列出用例、运行全集和只运行弹窗测试；`--list`（列出）只说明能加载用例，不代表已通过。

```powershell
& '.\.venv\Scripts\python.exe' -B -m develop_tools.run_offline_tests --list
& '.\.venv\Scripts\python.exe' -B -m develop_tools.run_offline_tests --suite all
& '.\.venv\Scripts\python.exe' -B -m develop_tools.run_offline_tests --suite popups
```

使用 `--case`（单用例）时，从列出结果复制完整标识。使用 `--out`（报告目录）时，指定仓库内尚不存在的新目录；已有目录不会被覆盖。

退出码为：0 表示全部通过且没有跳过；1 表示执行失败；2 表示参数、依赖、样本或其他准备条件不满足。已登记样本缺失时直接报错，不跳过。预期失败也不当作回归通过。

## 遇到问题后怎么补

1. 保留原截图，把脱敏副本放到 `develop_tools/test/fixtures/`（样本目录）。遮盖账号标识，保留原尺寸及识别区域；裁剪图写清裁剪范围。采集时间不知道就留空，不从文件名推断。
2. 在 `manifest.json`（样本清单）登记稳定编号、相对路径、尺寸、`sha256`（内容校验值）、服务器、场景、来源和 `used_by`（使用用例）。图片内容变更后先确认原因，再更新校验值。
3. 通过公共加载器使用样本，补预期识别、点击位置、禁止动作和结束状态的断言。新增测试模块需要同时登记到入口，先跑单项，再跑相关测试集。

当前清单中的老裁剪图保留原有来源说明；来源未记录的直接注明未知，不补写采集日期。本次活动提示的完整图与新裁剪图记录了来源文件名、原图摘要及脱敏或裁剪范围。

回放按获取截图推进，点击只记录动作。流程用例还要明确放入重复画面、点击未生效和最终画面；帧用完仍未结束就失败。时间由公共时钟推进，不依赖真实等待，也不因为点击发生就视为成功。

## 结果保存在哪里

默认报告放在 `develop_tools/out/results/offline-tests/`（离线报告目录），每次运行使用新的子目录。`result.json`（结构化结果）记录用例、状态、耗时、识别区域、截图与动作；`output.log`（测试日志）保留断言输出。失败时附上最后画面和关联登记样本，规则测试没有截图时保留文字断言。

基础测试会故意制造失败和跳过，检查退出码、报告和附件。它生成的检查材料和其他测试临时数据一起在结束时清理。

默认离线回归、桌面回归和启动验证在运行时检查已完成的报告。桌面入口通过项目虚拟环境执行这一步。完成满 7 天的报告整份移动到 `.cache/test-results/`（历史测试报告目录）。也可在仓库根目录手动运行：

```powershell
& '.\.venv\Scripts\python.exe' -B -m develop_tools.test_output
```

中断且未写完的报告、手动指定位置的报告及以前按天保存的目录可按需检查和整理。
