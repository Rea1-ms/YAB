# 离线截图回归

先把遇到过的问题留下来。之后修识别或流程时，使用同一批截图复查，逐步增加场景。

当前入口只运行明确登记的测试，不会自动搜索历史测试，也不会连接模拟器或读取账号配置。已有普通、困难推图测试需要真实设备，仍单独手动运行。

## 活动提示的判定约定

进游戏前的活动提示和公告使用不同的特征。活动提示检测左下角两种“不再显示”图标中的任意一种，命中后点击右上角关闭位置；不再把右上角叉号作为匹配条件。以 1280×720 为基准，关闭位置为（1173，75），实际点击继续由已有缩放逻辑转换。

公告仍需同时命中左侧工具栏和自己的关闭特征，关闭位置为（1214，43）。不要把活动提示改动套到公告，也不要用主页“小房子”图标判断进游戏前的提示。

新增同类问题时，先补完整脱敏截图，再检查各语言与缩放下的识别和点击；流程回放另放入重复画面、点击未生效及真正结束的画面。点击发生不能代替结束画面的确认。既有国服标题样本只是接入同一回归入口，不代表本轮修改了国服扫荡业务。

## 怎么运行

在仓库根目录使用已有虚拟环境。以下依次为列出用例、运行全集和只运行弹窗测试；`--list`（列出）只说明能加载用例，不代表已通过。

```powershell
& '.\.venv\Scripts\python.exe' -B -m develop_tools.run_offline_tests --list
& '.\.venv\Scripts\python.exe' -B -m develop_tools.run_offline_tests --suite all
& '.\.venv\Scripts\python.exe' -B -m develop_tools.run_offline_tests --suite popups
```

使用 `--case`（单用例）时，从列出结果复制完整标识。使用 `--out`（报告目录）时，指定仓库内尚不存在的新目录；已有目录不会被覆盖。

退出码为：0 表示全部通过且没有跳过；1 表示执行失败；2 表示参数、依赖、样本或其他准备条件不满足。已登记样本缺失时直接报错，不跳过。预期失败也不当作回归通过。

## 遇到问题后怎么补

1. 保留原截图，把脱敏副本放到 `develop_tools/test/fixtures/`（样本目录）。遮盖账号标识，保留原尺寸及识别区域；裁剪图写清裁剪范围。采集时间不知道就留空，不从文件名推断。
2. 在 `manifest.json`（样本清单）登记稳定编号、相对路径、尺寸、`sha256`（内容校验值）、服务器、场景、来源和 `used_by`（使用用例）。图片内容变更后先确认原因，再更新校验值。
3. 通过公共加载器使用样本，补预期识别、点击位置、禁止动作和结束状态的断言。新增测试模块需要同时登记到入口，先跑单项，再跑相关测试集。

当前清单中的老裁剪图保留原有来源说明；来源未记录的直接注明未知，不补写采集日期。本次活动提示的完整图与新裁剪图记录了来源文件名、原图摘要及脱敏或裁剪范围。

回放按获取截图推进，点击只记录动作。流程用例还要明确放入重复画面、点击未生效和最终画面；帧用完仍未结束就失败。时间由公共时钟推进，不依赖真实等待，也不因为点击发生就视为成功。

## 结果保存在哪里

默认报告位于 `develop_tools/out/offline-tests/`（离线报告目录），每次新建独立子目录。`result.json`（结构化结果）记录用例、状态、耗时、识别区域、截图与动作；`output.log`（测试日志）保留断言输出。失败时附上最后画面和关联登记样本，规则测试没有截图时保留文字断言。

基础测试会故意制造失败和跳过，核对退出码及报告。内部预期错误被正确识别后，这项基础测试才通过；其诊断目录会保留，不能把内部错误报告当成全集结果。

报告目录已被版本控制忽略，不自动清理。确认不再需要时由使用者手动删除。这批仅做本地离线回归，未接入云端，也不代表实机完整流程已经验证。
