# 桌面安装器维护

这里整理安装器复选框素材、卸载残留和发行包的检查方法。当前桌面版继续使用 Electron（桌面壳）配套的 NSIS（安装器工具），普通构建使用仓库中保存的素材与原生插件。

## 先找对应入口

下面的路径从仓库根目录查找：

| 修改内容 | 主要入口 |
|---|---|
| 原始复选框图形、来源和许可 | `desktop/assets/checkbox`（复选框素材目录） |
| 生成多尺寸图片和摘要清单 | `desktop/generate_checkbox_assets.cjs`（素材生成工具） |
| 重建插件、校验并嵌入图片 | `desktop/build_installer_ui.py`（插件构建工具） |
| 主题颜色与原生控件状态 | `desktop/native/installer-ui.cpp`（绘制插件源码） |
| 卸载文件清单和另外写入的图标 | `desktop/electron-builder.cjs`（打包配置） |
| 数据保留选择与空目录清理 | `desktop/installer.nsh`（安装与卸载扩展） |
| 实际编译、绘制和策略检查 | `desktop/test/installer.test.cjs`（安装器回归） |

页面、提权、译文和进度的详细约定见仓库中的 `desktop/installer-guide.md`（安装脚本说明）；历史验证范围记录在 `desktop/maintenance.md`（桌面维护说明）。

## 复选框图形从哪里来

三种原始矢量图直接来自 [Fluent UI System Icons（微软系统图标库）](https://github.com/microsoft/fluentui-system-icons)，固定上游版本记录在素材清单中，MIT（宽松开源许可）原文随素材保存。参考仓库主要有：

- [WPF UI（桌面界面库）](https://github.com/lepoco/wpfui/blob/main/src/Wpf.Ui/Resources/Fonts.xaml)：把图标作为随程序发布的资源管理。
- [FluentIcons（多框架图标封装）](https://github.com/davidxuang/FluentIcons)：将图形选择、尺寸和前景色分开设置。

本项目使用微软原图，没有复制这两个项目的代码或引入其控件框架。图片只保存透明度轮廓，深浅色主题及禁用、悬停、按下的颜色由插件设置。

当前生成 16、20、24、28、32、40、48、56、64 像素九种尺寸，覆盖未勾选、勾选和半选三种状态，共 27 张图片。图片内嵌到 `YabInstallUI.dll`（原生绘制插件），运行安装器时不依赖外部素材路径。控件继续由系统处理点击、空格键、焦点和辅助功能；高对比度、绘图库或素材不可用时使用系统绘制。

## 修改素材后怎么构建

只修改说明文档时，无需重新生成素材或打包。修改原始图形时，先在素材目录保留来源版本、原图和许可，再执行下面的流程。

在仓库根目录运行以下命令。第一步使用项目已有的 Electron（桌面运行环境）生成图片、资源头文件和摘要清单；第二步重建 32 位插件，需要本机已有微软桌面构建组件。

```powershell
Set-Location desktop
node generate_checkbox_assets.cjs
Set-Location ..
./.venv/Scripts/python.exe -B desktop/build_installer_ui.py
Set-Location desktop
pnpm test
pnpm run dist
```

每一步成功后再执行下一步。普通发行直接使用已经保存的素材与插件，不需要运行前两步。原生插件变化后，安装包和完整压缩包都要重新生成。

构建工具会先校验原图、图片和资源头文件的摘要。出现不匹配时，先检查来源记录、文件内容和换行格式，再重新生成，不能跳过校验。`desktop/.gitattributes`（桌面换行约定）将原始矢量图和生成头文件固定为 LF（换行格式）；提交前也要检查暂存及检出过滤后的字节摘要，避免只在当前工作区构建成功。

## 卸载残留先看归属

程序文件按本次构建清单移除，不能递归清空安装根目录。默认勾选“保留应用数据”；取消勾选后才清理当前安装的配置和当前用户默认运行数据，覆盖更新始终保留数据。原 BAAS（旧版程序）数据和环境变量指定的其他目录不自动清理。

`uninstallerIcon.ico`（卸载显示图标）由安装器在打包后另外写入，不在应用文件清单中。因此清理脚本需要在存在卸载图标的编译条件内单独处理它，再尝试非递归移除空的安装根目录。成功回调最多重试三次；目录中仍有配置或用户新增文件时保留。

排查时检查本次生成的清理脚本，分别编译有图标和无图标的分支，并把移除操作替换为路径日志。路径日志能验证范围与顺序，不能作为实际删除已经完成的证明。

### 系统开始菜单备份

`HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\AppListBackup`（当前用户的系统开始菜单备份）由 Windows（视窗系统）维护。其备份记录中出现 `W~org.baas.desktop`（兼容的应用身份）时，不能仅据此判断程序仍安装或卸载失败。

当前安装器仍通过打包器注册快捷方式、应用身份和卸载信息，卸载时保留对应的正常注销流程。排查残留时，先核对这些自有项目，再区分系统共享备份；不要清空整个备份项或按应用标识删除共享值。

现有记录没有证明某个事件数字的含义或精确写入时机，文档也不据此推断。用户使用时的卸载方式见 [卸载说明](../usage_doc/uninstall.md)。

## 怎么核对发行结果

安装和卸载清单均声明 PerMonitorV2（第二代逐屏缩放）。跨屏时系统调整标准对话框和控件，原生插件按原始字号缩放控件字体，保留微软雅黑和标题粗细，避免系统用模板字体覆盖运行时设置。插件随后刷新标题栏图标、高清侧栏、提权按钮宽度及进度覆盖层。复选框按当前窗口缩放选择素材，无需逐档编写布局。

安装器回归会在本机可用屏幕之间移动隔离预览，检查中文欢迎页、进度页和完成页的字体名称、字号、粗细与图形资源，并保存实际画面和控件尺寸；本机已实测 125% 与 200% 往返。没有不同缩放屏幕时，会明确区分尺寸模拟和真实跨屏验证，不修改系统显示设置。

1. 桌面回归通过后，核对真实控件的深浅色像素与点击、空格状态。本轮已有检查覆盖勾选、未勾选、禁用、按下和半选；记录实际显示缩放，素材尺寸覆盖不等于所有缩放下的布局都已实测。
2. 核对插件中的嵌入图片及包内原图、素材、许可与本次输入一致；再检查正式安装器使用的头文件、译文和插件，不能只看独立预览。
3. 在独立目录中只解压读取安装包和完整压缩包，比较共同应用文件的清单与摘要，不运行真实安装或卸载。当前打包器只给安装包增加 `resources/elevate.exe`（提权辅助程序）；单独核实并记录这项差异，其他差异继续追查。
4. 保存两个发行文件的摘要，说明本次检查范围。仅修改安装器且运行内容未变时，可以沿用此前应用离线启动验证；重建产物不能写成刚执行过离线首启。构建目录和验证缓存保留，按用户约定手动清理。

这些步骤使用项目现有入口。仅放在本机临时目录的验证脚本不是维护依赖，不应要求其他开发者先找到同名脚本。

## 弹窗主题验证

系统提示不会自动继承主窗口颜色。原生插件需要在初始化、界面和安装／卸载区段的实际执行线程中分别启用消息框绘制；不能只在界面定时器里弹出测试提示就认为工作线程也已适配。

现有回归检查早期初始化、真实安装和卸载区段中的消息框，确认线程不同，核对深浅色、模拟高对比度、正文和按钮区像素及原生按钮返回值。程序运行和文件占用检查使用相同类型的提示，但测试不会查询、结束真实程序或删除文件。

安装目录使用现代系统文件夹选择窗口，选择后仍回填原路径框，取消保留原值；不可用时回退原选择器。本机已验证深色背景、选中及取消。系统文件选择也检查当前系统主题，不以模拟应用浅色宣称真实浅色系统已通过。

桌面壳的错误、说明和回退提示共用应用弹窗，随系统深浅色变化，并支持高对比度配色、默认焦点、取消键和可复制的长日志。网页内弹窗继续使用共享主题变量。

构建会校验卸载器提前初始化主题的模板确实生效；未加载生成模板时直接停止编译。上游模板锚点变化也会报错，修改后需同时核对原有检查和重试内容。
