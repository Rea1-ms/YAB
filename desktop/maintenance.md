# 桌面维护说明

这里记录桌面版目前采用的做法，以及修改后需要检查的内容。安装和使用方式见 [桌面应用说明](README.md)。

## 按修改内容找入口

| 修改内容 | 主要文件 | 对应检查 |
|---|---|---|
| 安装器路径、深浅色、字体、实时操作文字 | installer.nsh（安装扩展）、installer-ui.nsh（界面扩展） | test/installer.test.cjs（安装器回归）及正式安装包编译 |
| 复选框绘制与原生状态 | installer-controls.nsh（控件绘制） | test/installer.test.cjs（安装器回归）的真实绘制、点击和空格键检查 |
| 图标、安装侧栏 | generate_assets.py（素材生成工具）、assets（素材目录） | 图标尺寸、实际字体及目标位图尺寸检查 |
| 网页监听、桌面浏览器入口 | webui.cjs（桌面监听设置）、main.js（主进程）、server/webui_settings.py（后端监听设置） | test/webui.test.cjs（桌面监听回归）、develop_tools/test/test_webui_settings.py（后端监听回归） |
| 帮助页配色 | webapp/src/lib/help-document.ts（文档样式处理）、webapp/src/lib/pages/Update.svelte（更新与帮助页） | test/help.test.cjs（隐藏浏览器渲染检查） |
| 离线环境、配置迁移 | runtime.cjs（运行准备）、bundle.py（后端资源打包） | test/runtime.test.cjs（运行环境回归）及隔离数据下的完整发行验证 |

表中目录以桌面应用目录为准；server、webapp、develop_tools（后端、前端、开发工具目录）从项目根目录查找。

## 安装器继续使用配套定制版

暂沿用 electron-builder（桌面打包工具）配套的 NSIS（安装器工具），本轮构建使用 3.0.4.1。
准确版本以锁文件和构建日志为准。官方发布了更高版本，也不能只替换编译器就算升级完成；
需要重新验证模板、插件、正式安装器和卸载器的兼容性。

当前界面是在配套安装器上定制，没有引入 WinUI 3（微软界面框架）。修改时保留这些约定：

- 浏览文件夹后，原路径框立即显示包含应用子目录的最终路径。手动填写完整路径时，开始安装不得再追加目录。
- 卸载默认保留应用数据，覆盖更新始终保留。测试中用路径日志替代实际删除，不操作用户的真实配置。
- 在 customCheckAppRunning（程序运行检查扩展）恢复实时状态文字时，继续调用原有程序运行检查。
  打包器会因该扩展跳过一部分默认声明，扩展中仍需提供对应的进程变量和查询脚本。
- 正式编译将警告作为错误。新文案只支持部分语言时，明确按语言输出并提供英文回退，
  不要让其他语言缺少字符串，也不要为通过编译关闭警告检查。
- 打包后生成安装扩展脚本时，一起复制 installer-ui.nsh 和 installer-controls.nsh（界面与控件扩展），避免预览成功而正式安装包缺文件。

## 高分屏与控件绘制

字体、图标、位图应分别处理。当前声明按启动时的显示缩放绘制，并选用微软雅黑界面字体；
这不代表支持在不同缩放的显示器之间移动时动态调整。

主仓 assets/logo.png（标志原图）是桌面素材来源。修改原图后，在项目根目录运行
`.venv/Scripts/python.exe desktop/generate_assets.py`（素材生成命令），将生成的多尺寸图标和四倍侧栏一并保存。
普通发行构建直接使用这些素材，不要求用户重新生成。
侧栏用 HALFTONE（高质量缩放模式）绘制到控件实际像素大小，不能只放大原来的低分辨率位图。

复选框继续由系统处理点击、空格键、焦点和勾选状态，只定制绘制；高对比度或绘图库不可用时使用系统绘制。
修改后，既要检查实际像素，也要检查状态变化。只通过脚本编译，不能证明图形已经画出来。

当前 32 位调用接口向 GDI+（图形库）传角度和笔宽时，需要传单精度浮点数的位模式。
普通浮点参数写法曾出现“编译成功、实际图形未绘制”的情况；保留现有笔宽转换和原生控件回归，避免再次引入。
深色按钮类型判断使用数值比较；禁用单个控件主题时保留现有空格参数，空字符串会恢复默认主题。

## 桌面窗口与浏览器共用服务

默认监听 127.0.0.1:22267。托盘中的“在浏览器中打开”使用同一个服务地址，退出应用后服务也会停止。
端口被占用时明确报错，不自动改用随机端口，以便浏览器地址保持稳定。

“设置 → 网页访问”保存全局设置，与当前选中的账号无关：

- 发行版保存在程序旁的 config/webui.json（网页配置），源码版默认使用源码目录中的同名文件。
  YAB_CONFIG_DIR（配置根目录环境变量）可以覆盖位置。
- 桌面端 BAAS_DESKTOP_PORT（端口环境变量）、源码端显式启动参数优先于保存值。
  缺少文件使用默认值；坏文件、非法地址或端口明确报错，布尔值不能当作整数端口接受。
- 页面区分已保存设置和当前监听设置。保存后重启生效，不自动中断正在运行的任务。
- 非回环地址仍要求 BAAS_WEBUI_TOKEN（访问密码环境变量）。密码不写入配置，启用后桌面窗口和浏览器均需登录。

改动时同时检查桌面和后端读取规则，不能只改其中一端。
接口检查应确认保存回执没有改变当前监听，并在重启后确认新端口实际可访问。

## 帮助页有独立的深色画布

内嵌文档不会继承应用主题。只在外层设置深色，或给文档设置白色文字加透明背景，仍可能出现白底白字。

当前做法是解析完整文档，在真实 head（头部）末尾添加主题样式，明确设置文档和正文的背景、文字及深色配色。
原文中的黑白文字、亮色高亮也一起调整，保留彩色强调和图片。
不需要批量重写 src/descriptions（帮助源文档目录）。文档使用受限内嵌页显示，外链在新窗口打开。

隐藏浏览器检查读取真实帮助文档，核实计算后的背景、文字、链接和旧高亮样式。
它使用独立的浏览器数据目录，不启动后端或连接设备。
若工具沙箱报告应用容器无法读取开发运行环境，应按工具权限流程在正常权限进程重跑；
不要关闭应用沙箱或放宽目录权限来掩盖检查失败。

## 修改后的检查顺序

先准备前端和桌面目录的锁文件依赖。后端使用项目已有的 Python 3.11（运行环境）虚拟环境。

1. 在项目根目录运行 `.venv/Scripts/python.exe -B -m unittest -q develop_tools.test.test_webui_runtime develop_tools.test.test_webui_access develop_tools.test.test_adb_devices develop_tools.test.test_webui_settings`（后端回归）。
2. 在前端目录运行 `pnpm run check`（类型及界面检查）与 `pnpm build --emptyOutDir false`（保留旧产物的网页构建）。
3. 在桌面目录运行 `pnpm test`（桌面回归）。安装器检查使用真实编译器，隐藏浏览器检查使用前端的 TypeScript（类型语言）依赖；不安装程序或删除真实数据。
4. 涉及发行内容时运行 `pnpm run dist`（完整发行构建），确认安装包和完整压缩包都已生成。仅修改本文档时无需重复打包。
5. 使用隔离配置验证完整压缩包的离线首启、识别就绪、再次启动、配置持久化和环境复用；监听变更还要检查修改端口后重启、认证及实际网页通信。不要连接用户设备或复用真实账号配置。

本轮在 2026-11-06 完成了 17 项桌面回归、49 项后端回归、前端检查和正式构建，
并验证了完整压缩包的离线启动、端口变更与实际接口收发。
字体检查对应本机 125% 缩放；侧栏检查覆盖 100% 至 400% 的目标位图尺寸，
不等于这些比例下的全部布局或跨屏行为都已实测。系统文件夹选择窗口此前仍为浅色。
这些记录不作为后续修改自动通过检查的依据。

构建产物、失败目录和隔离测试数据均保留，按用户约定手动清理，不自动删除。
