# 安装脚本说明

目前继续使用 electron-builder（桌面打包工具）配套的 NSIS（安装器工具）。这里说明项目里的扩展写法，安装和构建命令见 [桌面应用说明](README.md)。

## 文件怎么分工

`.nsi`（主脚本）是编译入口，`.nsh`（头文件）被主脚本包含。本项目的主脚本来自打包器模板，定制部分放在头文件中：

| 文件 | 内容 |
|---|---|
| installer.nsh（安装扩展） | 运行检查、卸载数据选择、成功后的空目录清理 |
| installer-ui.nsh（界面扩展） | 主题、目录页、字体、侧栏及进度显示 |
| installer-pages.nsh（页面状态） | 安装欢迎页、协议接受记录、提权后恢复及后退 |
| installer-i18n.nsh（语言加载） | 加载标准语言与项目译文，选择英文回退 |
| installer-translations（译文目录） | 简体中文、繁体中文、英文自定义文案 |
| installer-controls.nsh（控件入口） | 调用原生绘制插件 |
| installer-progress.cjs（进度生成） | 在打包器解压模板中加入阶段提示，保留原有文件操作 |
| electron-builder.cjs（打包配置） | 复制这些文件，按本次程序清单生成移除脚本 |

构建时生成的 installer-generated.nsh（组合头文件）在发行目录中，不直接修改它。名称和版本取自 package.json（项目元数据），不在译文里写死。

## 编译时和运行时

`!include`（包含头文件）、`!define`（定义编译常量）、`!macro`（声明宏）和 `!insertmacro`（展开宏）在编译时处理。
宏本身不会在运行时被调用，而是把里面的指令放到使用位置。

`Function`（函数）、`Call`（调用）、`StrCpy`（赋值）等在安装器运行时执行。`${if}`（运行时条件宏）会生成判断指令，`!if`（编译时条件）则决定哪些指令进入安装包，两者不能混用。

例如，欢迎页设置标题时引用一个语言字符串：

```nsis
!define MUI_WELCOMEPAGE_TITLE "$(yabWelcomeTitle)"
!insertmacro MUI_PAGE_WELCOME
```

第一行给标准页面提供标题，第二行生成欢迎页。`$(yabWelcomeTitle)`（标题语言字符串）在运行时按当前语言取值；译文中的 `${YAB_DISPLAY_NAME}`（名称与版本）在编译时展开。
欢迎和卸载正文直接使用 Modern UI（现代安装界面）的标准译文，仅标题加入项目版本。

界面插件可能把结果放入栈中，`Pop`（取栈）必须与实际返回值对应；删除控件创建语句后，不能留下对应的取栈。
`MUI_HEADER_TEXT`（页标题宏）始终需要标题和副标题两个参数，副标题不用时传空字符串。

## 提权后为什么不重复协议

多用户页面使用打包器配套的 UAC（用户账户控制）插件。选择为所有用户安装后，插件启动提权的内部实例，原实例等待结果。

外部实例只有在用户真正接受协议后才记录接受状态。内部实例读取这份状态，首次经过时跳过欢迎页和已接受的协议，进入目录页。
跳过标志只使用一次，因此点击“上一步”仍能返回协议和欢迎页。若提权发生在初始化阶段、用户尚未接受协议，仍显示协议页。
更新流程原有的跳页判断也保留。

这一部分参考了 [打包器的协议恢复处理](https://github.com/electron-userland/electron-builder/blob/42eb34fc6a22990762735e563227f4914074dc75/packages/app-builder-lib/templates/nsis/assistedInstaller.nsh)，未替换当前编译器版本。

## 返回页面时为什么要清除盾牌

各页共用同一个下一步按钮。打包器的安装范围页在切换单选项时更新提权盾牌，但没有在返回前页时清除，按钮便会保留上一页的状态。
界面扩展在每页进入前发送 `BCM_SETSHIELD`（设置提权盾牌消息）清除状态，安装范围页随后按真实提权条件重新设置。
这样既保留原有权限判断，也保证欢迎页和协议页不会显示残留盾牌。

原生绘制将盾牌与文字作为一组居中，并用实际绘制文字的方式计算宽度，保持快捷键符号的处理一致。
按钮放不下时按所需宽度扩展，同时左移上一步；清除盾牌后恢复原布局，避免图标贴边或按钮重叠。
回归使用真实安装范围页验证前进、后退、单选切换及深浅色像素，不触发真实提权。

## 译文怎么维护

参考 [qBittorrent（开源下载工具）的独立译文目录](https://github.com/qbittorrent/qBittorrent/tree/master/dist/windows/installer-translations)，业务脚本只引用语言字符串，译文按语言保存。
加载使用官方 LangFile（语言文件）宏；已有译文缺少词条时回退英文并发出警告，编译仍按警告即错误处理。
暂未提供整种语言的译文时，自定义文案使用英文，标准按钮及正文仍使用该语言的标准翻译。

欢迎正文沿用标准页面，移除文件的简中文案沿用 qBittorrent（开源下载工具）的“删除文件”，只补充本项目必需的数据选项和状态。
安装与卸载共用运行检查回调，回调结束后按实际函数上下文恢复相应状态，避免卸载时出现“正在安装”。

目录页说明沿用 Notepad++（文本编辑器）的句式，显示构建名称版本，并用标准的安装提示作为末句；路径框仍直接显示最终安装目录。
启用 `MUI_ABORTWARNING`（安装退出确认）和 `MUI_UNABORTWARNING`（卸载退出确认），复用标准的是／否对话框及各语言译文，取消和右上角关闭均由安装器统一处理。
系统消息框不会自动继承深色主题；原生插件只为当前向导拥有的是／否消息框补充绘制，保留系统布局、键盘操作与返回值。
浅色及高对比度使用系统外观，不修改系统设置或提权窗口。

## 安装进度怎样计算

原进度条由安装脚本和解压插件共用。脚本按指令计数，解压插件按压缩包内容计算，
两者会改变范围并恢复各自的位置；直接把原始值当总进度，会出现 100% 后退回 69% 的情况。

现在保留原控件供打包器使用，另用一条原生进度条显示总进度，状态文字显示当前阶段：

| 当前操作 | 总进度区间 |
|---|---|
| 准备安装、检查进程和处理旧版本 | 0%～5% |
| 释放内置安装包 | 5%～15% |
| 解压程序文件 | 15%～65% |
| 写入程序文件 | 65%～90% |
| 保存安装信息、缓存安装器、注册和创建快捷方式 | 90%～98% |
| 完成安装收尾 | 98%～99% |
| 安装成功回调 | 100% |

这是按阶段分配的估算进度，不代表剩余时间。阶段内范围变化、原始值恢复和文件占用重试都不使总进度倒退；
状态文字与显示条使用同一个值。只有成功回调可以显示 100%，中止或失败不能算完成。

构建时从当前安装的打包器读取解压模板，只在现有指令前后加入阶段调用。
通过构建参数提前添加包含目录，使用生成的解压头文件；主脚本和卸载程序生成仍走原打包流程。
未改动依赖目录，也未重写复制、文件占用重试或取消逻辑。模板锚点发生变化时构建报错，要求重新核对。
生成的 nsis-progress（进度扩展目录）保留在本次发行目录中，便于检查实际输入。

进度回归会向真实控件发送原始 100%→69%、范围切换、累加和复制重试等消息，检查总进度与文字一致；
另用小型压缩包实际执行原解压及复制宏，确认正式构建使用的包含路径和阶段有效。

## 卸载结束怎样清理

程序文件按构建清单移除。应用数据默认保留，只有用户取消勾选时，才移除当前安装的配置和当前用户默认 YAB 数据目录；更新始终保留数据。
不再查找或清理原 BAAS 数据目录，显式指定到其他位置的数据也保留。

最后使用 `RMDir "$INSTDIR"`（只移除空的安装目录）。不带递归参数时，目录内有任何文件都会失败并保留，适合保留配置和用户新增文件。
成功回调在移除程序、快捷方式和注册信息之后执行，先切到临时目录，再最多尝试三次；更新时跳过该步骤。

[qBittorrent（开源下载工具）的卸载脚本](https://github.com/qbittorrent/qBittorrent/blob/master/dist/windows/uninstaller.nsh)同样对安装根目录使用非递归移除。
[Notepad++（文本编辑器）的卸载脚本](https://github.com/notepad-plus-plus/notepad-plus-plus/blob/master/PowerEditor/installer/nsisInclude/uninstall.nsh)也写明：“These folders will be deleted only if they are empty”（这些文件夹仅在为空时删除）。

打包器模板还会注销快捷方式和应用标识，并删除本程序的安装及卸载注册信息。
用户报告的 AppListBackup（系统开始菜单备份）属于系统共享记录，不是本程序独占的卸载项，不能整项删除。
安装标识继续用于现有 YAB 版本的覆盖升级。

## 怎么检查

现有安装器回归会真实编译并运行隔离预览，检查路径、绘制、页面前进后退、协议接受状态，以及多语言版本标题和卸载状态。
移除操作替换为路径日志，覆盖默认保留、主动清理、更新保护、空目录清理的时机和有限重试，不执行真实文件删除。

脚本检查通过后，还要编译正式安装包，确认全部头文件、译文和插件都已复制。
运行准备代码有变化时，应完整构建应用，并用隔离数据检查首次启动和再次启动，不能只重编安装器。
