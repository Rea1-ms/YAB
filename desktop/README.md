# YAB Desktop（桌面应用）

用 Electron 包一层 YAB WebUI：主进程负责拉起后端 `python -m server`、探测就绪后加载
`http://127.0.0.1:<port>/`，并提供系统托盘常驻。发行包包含源码、网页、识别程序、
独立 Python（运行环境）、uv（环境管理工具）和锁定版本的离线依赖，不需要用户另装开发工具。
另有轻量包，首次启动时在线准备解释器和依赖，可使用内置或系统的依赖管理工具。

修改安装器、网页监听或帮助页时，可先看 [桌面维护说明](maintenance.md)，其中记录了当前约定、检查入口和验证范围。
安装脚本的写法、提权和译文组织见 [安装脚本说明](installer-guide.md)。

## 目录

```
desktop/
├─ package.json     # 启动、验证和发行包构建入口
├─ pnpm-lock.yaml   # 锁定依赖（electron ^45）
├─ main.js          # 主进程全部逻辑（后端管理/窗口/托盘/清理/冒烟）
├─ preload.js       # contextBridge 暴露 process.versions 等无害信息（window.yabDesktop）
├─ assets/          # 多尺寸图标与安装器侧栏，来自主仓 assets/logo.png
└─ README.md
```

`node_modules/` 已被 `desktop/.gitignore` 忽略。注意：Electron 45 起包内不再带
postinstall，`pnpm install` 只装 JS 包；**平台二进制在第一次运行 `electron` 时自动下载**
（`node_modules/electron/dist/`，约 250MB，可用环境变量 `ELECTRON_MIRROR` 指定镜像加速）。

## 开发运行

前置：仓库根执行过 `uv sync --python 3.11`（存在 `.venv`），且 `webapp/dist/index.html`
已构建（`uv run python -m server.frontend`，或任由首次启动自动构建）。

```powershell
# 方式一：仓库根执行
desktop\node_modules\.bin\electron desktop

# 方式二：
cd desktop
pnpm install   # 首次运行 electron 时会自动下载平台二进制
pnpm start
```

## 冒烟模式（CI / 无头验证）

不创建任何窗口，走同一套逻辑：拉起后端 → 轮询 `/api/health` → 成功打印 `SMOKE OK`
退出码 0；失败打印 `SMOKE FAIL` + 原因（含后端输出尾部）退出码 1。退出前会杀掉后端进程树。

```powershell
cd desktop
pnpm run smoke
```

注意：首次运行若 `webapp/dist` 缺失，后端会在启动时构建前端，可能超过 90s 就绪预算；
CI 建议先构建前端再跑 smoke。冒烟模式不申请单实例锁，可与其他实例共存。

## 环境变量

已有环境变量保留原来的 BAAS（上游项目名）前缀，以兼容启动脚本；新增 YAB_CONFIG_DIR（配置位置环境变量）用于指定配置根目录。

| 变量 | 作用 | 默认 |
|---|---|---|
| `BAAS_PYTHON` | 指定后端 python 解释器（需已装好依赖） | 不设则用候选链 |
| `BAAS_DESKTOP_PORT` | 覆盖设置中的网页端口 | 使用 config/webui.json，缺省为 22267 |
| `BAAS_ROOT` | 指定已有的源码或后端目录，跳过内置运行环境准备 | 开发期为 `desktop/` 上级 |
| `BAAS_DESKTOP_DATA` | 指定运行环境、日志和回退备份的数据目录 | 系统当前用户的应用数据目录 |
| `YAB_CONFIG_DIR` | 指定桌面发行包的配置根目录 | 可执行程序同级的 config（配置目录） |

后端可执行文件候选优先级（`main.js` 的 `backendCandidates`）：

1. `BAAS_PYTHON`
2. `<仓库根>/.venv/Scripts/python.exe`（Windows）/ `.venv/bin/python`（其他）
3. `<仓库根>/webui.exe` / `YAB.exe`（兼容旧冻结产物）
4. 系统 `python`（PATH）

发行包始终使用专用环境；完整包离线准备，轻量包在线准备。以上候选链仅用于开发或主动指定源码目录的情况。
服务以程序目录作为工作目录，按相对路径读取配置和素材。

## 浏览器访问

桌面窗口与浏览器共用一个网页服务，默认地址为 `http://127.0.0.1:22267/`，
托盘菜单中的“在浏览器中打开”可以直接打开当前地址。应用退出后网页服务也会停止。

在“设置 → 网页访问”中修改监听地址和端口，保存到程序旁的 `config/webui.json`，
完全退出应用并重新启动后生效。此设置适用于所有任务配置。源码启动也读取此文件，
命令行 `--host`（监听地址）和 `--port`（监听端口）可以覆盖保存值。
端口被占用时会明确提示，不会自动改成随机端口。

局域网访问可将监听地址改为 `0.0.0.0`，但需先通过 `BAAS_WEBUI_TOKEN`（访问密码环境变量）
设置密码再启动应用；随后使用本机的局域网地址访问。密码不写入配置文件，
启用密码后桌面窗口和外部浏览器均需登录。

## 行为说明

- **单实例**：`app.requestSingleInstanceLock`，二次启动聚焦已有窗口。
- **窗口**：1280×800（最小 960×640），深色背景；就绪前显示内置启动页。
  页面内导航到外部域名会用系统浏览器打开（`will-navigate` / `setWindowOpenHandler`）。
- **启动过程**：独立启动页显示当前步骤、总体进度、已用时间和实时日志，可关闭自动滚动查看前面的输出。
  总体进度按实际步骤估算，下载或安装期间不会按计时器虚增；只有后端、识别服务就绪且主界面加载完成才算成功。
  运行环境准备完成后显示其完整位置。失败和重试保留当前日志，错误信息也会显示在日志区。
  主界面加载成功后，进度到达 100%，短暂显示“准备就绪”并淡出启动页；系统启用“减少动态效果”时直接进入。
- **托盘**：右键菜单 = 显示主窗口 / 重新载入页面 / 在浏览器中打开 / 退出；左键单击 = 显示窗口。
  点窗口关闭按钮 = 隐藏到托盘（首次隐藏弹气泡提示）。**真正的退出只有托盘菜单一条路**。
- **退出清理**：`before-quit` / 托盘退出时，Windows 用 `taskkill /PID <pid> /T /F` 杀
  进程树，其他平台 `SIGTERM`（3s 后 `SIGKILL`），最多等 8s 兜底退出。
- **后端崩溃**：运行期后端进程退出会弹错误框（附最近 200 行输出尾部）并退出整个应用。
- **环境自愈**：若宿主环境泄漏了 `ELECTRON_RUN_AS_NODE=1`（某些开发工具的终端会这样），
  main.js 检测到后自动以干净环境用 electron 本体重启自己，`pnpm start` / `pnpm run smoke`
  行为不受影响。
- **macOS**：行为简化为与 Windows 一致（关闭隐藏到托盘、托盘菜单退出），未做 Dock 菜单
  等 macOS 惯例适配。

## 关闭窗口与轻量模式

首次关闭窗口会询问是否开启轻量模式，“下次不再提示”默认勾选；选择后会记住对应操作。
取消或关闭提示框会保留主窗口；取消勾选后，本次按选择操作，以后仍会询问。
设置页的“桌面应用 → 关闭窗口时的操作”可随时改为“仅关闭窗口、开启轻量模式、询问”，保存后立即生效。

“仅关闭窗口”会隐藏到托盘，保留页面；“开启轻量模式”会销毁页面，后端、识别服务和任务继续运行。
点击托盘或“显示主窗口”会重新加载界面，恢复原来的页面、窗口位置和大小；未保存的输入会丢失。
重新载入页面也能恢复已释放的窗口，不会重新准备环境或启动另一份后端。

默认询问，选择保存在应用数据目录的 desktop-settings.json（桌面设置文件），重启后继续使用。
启动准备尚未完成，或还有环境设置、提示窗口打开时，关窗仍按隐藏处理。退出整个程序仍会停止后端。
此模式只释放界面，桌面主进程继续常驻；不会改变硬件加速设置。

## 构建 Windows（视窗系统）安装包

目前支持 64 位系统。先准备好 Python 3.11（后端运行环境）、Node.js（前端构建运行环境）
和 pnpm（前端依赖管理工具）。前端运行环境建议使用 22.12 以上的 22 系列或 24 以上版本。

首次构建前，按主说明中的源码启动方式运行一次，等左下角 OCR（文字识别）指示灯变绿，
再回到终端按 Ctrl+C（中断运行）退出服务，确保识别程序和模型已经准备完成。
之后从仓库根目录执行以下命令；依赖安装会按锁文件准备兼容的后端和打包工具：

```powershell
uv sync --python 3.11
cd desktop
pnpm install --frozen-lockfile
pnpm run dist
```

构建过程先准备网页，再从 uv.lock（依赖锁文件）导出依赖、校验下载的源包并构建
wheel（可直接安装的依赖包），随后复制可搬迁的独立解释器和源码，最后生成安装包和完整压缩包。
解释器版本记录在 python-version（发行解释器版本文件），默认 3.11.14。
本机缺少该解释器时，构建工具会在构建缓存中下载；不会复制开发者的虚拟环境。

构建产物位于 `desktop/release/<构建时间>/`（发行目录）：

- `YAB-<版本>-x64-setup.exe`（可选择安装目录的安装包）。
- `YAB-<版本>-x64.zip`（完整压缩包），解压后双击其中的 `YAB.exe`（桌面入口）即可启动。

构建中间文件和离线依赖缓存保留在 `desktop/build/`（构建目录）。
在桌面应用目录改用 `pnpm run pack`（构建解压目录）可只生成应用目录，输出到同一时间目录下的
`win-unpacked/`（解压运行目录），便于本机验证。
当前生成的安装包不做代码签名。

### 轻量包

包名中的 system（系统工具）表示不内置 uv（依赖管理工具），启动时需要定位系统工具或手动选择本地文件。没有这一后缀的完整包和轻量包都内置工具。

| 包类型 | 文件名后缀 | 内置依赖管理工具 | 解释器与依赖 | PyCharm（开发工具）构建入口 |
|---|---|---|---|---|
| 完整包 | 无 | 是 | 内置，首次启动离线准备 | 05 应用目录；06 安装包与压缩包 |
| 轻量包 | lite（轻量） | 是 | 首次启动在线准备 | 07 应用目录；08 安装包与压缩包 |
| 系统工具轻量包 | lite-system（系统工具轻量） | 否 | 首次启动在线准备 | 09 安装包与压缩包 |

日常构建轻量包选择 08；09 适合已经准备好依赖管理工具的使用者。表中的应用目录可直接运行，不生成安装包或压缩包。

正式发包选择 **10 发包（三种安装包与压缩包）**：准备依赖和检查各执行一次，再依次构建完整包、内置工具轻量包和系统工具轻量包，共生成三个安装包、三个压缩包。任一步失败便停止；产物分别保存在本次三个构建对应的发行目录中，见控制台输出。

在桌面目录运行 `pnpm run dist:lite`（构建轻量安装包和压缩包）。
轻量包省去独立解释器与离线依赖包，保留网页、源码、识别程序和模型，默认带上依赖管理工具。
首次启动先选择工具和依赖源，再准备指定版本的解释器及锁定依赖；优先复用本机已由 uv（依赖管理工具）管理的相同版本，缺少时下载。应用依赖仍安装到独立环境，不使用开发虚拟环境。

- 工具可选内置、自动定位系统工具，或手动选择本地可执行文件。系统工具需为 0.9.0 或更新版本。
  当前工具的完整位置统一显示在路径框，版本显示在旁边；系统和内置路径可复制，手动选择时可直接编辑。
- 依赖源可选官方、阿里云、清华大学。版本和文件摘要仍按发行包锁定，镜像缺包时可调整设置重试。
- 设置保存在程序旁的 config/runtime-settings.json（运行环境设置），以后可从托盘的“运行环境”修改，下次启动生效。

`pnpm run pack:lite`（只构建轻量应用目录）可用于开发验证。
`pnpm run dist:lite:system`（构建仅使用系统工具的轻量包）连依赖管理工具也不内置，首次启动必须定位系统工具或选择本地文件。
轻量产物名称分别带 lite（轻量版）和 lite-system（系统工具轻量版），与完整包分开保存。
依赖源只用于依赖包。解释器使用工具默认的管理目录，也支持 UV_PYTHON_INSTALL_DIR（解释器管理目录）；需要下载时可用 UV_PYTHON_INSTALL_MIRROR（解释器下载镜像环境变量）指定镜像。
构建和运行优先复用已有的 UV_CACHE_DIR（共享下载缓存位置），未指定时使用各自的默认缓存目录。

新版的锁定依赖或解释器变化时，会新建环境，检查通过后再启用；只改源码、切换工具或下载源时复用相同依赖。
失败目录、缓存和旧环境均保留。完整包仍使用内置资源离线准备，不受轻量包下载设置影响。

安装器由 electron-builder（桌面打包工具）调用 NSIS（安装器工具）生成，定制入口是
installer.nsh（安装器扩展脚本）和 installer-ui.nsh（安装界面脚本）。浏览选好文件夹后，路径框会立即显示
包含 YAB 子目录的最终位置，不增加确认页；末级已是 YAB、旧桌面目录名，或目录中已有程序时，
不再重复追加子目录。手动编辑时直接使用填写的完整路径，开始安装时不会再改写。
安装和卸载窗口在启动时跟随系统的深浅色设置；启用高对比度时保留系统配色。
高分屏启用 PerMonitorV2（第二代逐屏缩放），移动到不同缩放比例的屏幕时，由系统调整标准控件和字体；
插件重新加载对应尺寸的标题栏图标、从高清原图重采样侧栏，并重新对齐进度文字、进度条及提权按钮。
安装进度条上方持续显示当前操作和进度；按钮、单选框及“保留应用数据”复选框使用统一绘制的外观，
仍保留原生键盘操作和辅助功能，高对比度模式使用系统控件。
协议标题居中、正文统一左对齐并自动换行，底部名称版本取消重叠阴影。
首次安装依次显示欢迎页、协议、安装范围、目录和进度页；欢迎页显示本次构建的名称和版本。
选择所有用户安装时，由 UAC（用户账户控制）插件提权，首次恢复时跳过已经接受的协议，直接进入安装目录页；
点击“上一步”仍能返回协议和欢迎页。欢迎正文使用标准界面译文，项目自定义文案按语言单独保存。
这是 NSIS（安装器工具）的界面定制，没有引入 WinUI 3（微软新界面框架）。
普通构建使用内置绘制插件；修改插件源码后运行 `.venv/Scripts/python.exe desktop/build_installer_ui.py`（重新生成绘制插件），需安装微软 C++ 桌面构建工具。
修改主仓标志后，可从仓库根运行 `.venv/Scripts/python.exe desktop/generate_assets.py`（重新生成桌面素材）；
该工具需要 Pillow（图像处理库），生成结果随源码保存，普通构建无需再次生成。
安装页面、图标、文字和安装行为均可继续定制。也可以使用 Inno Setup（安装器工具），
将 pack（生成应用目录）输出的整个 win-unpacked（解压运行目录）作为安装内容，另写脚本编译；
它不是桌面打包工具的内置目标，更新识别、快捷方式和卸载规则也需在新脚本中配置。

首次启动会校验完整文件清单，再使用内置解释器和离线依赖创建独立虚拟环境，整个过程
不访问依赖源，也不下载识别模型。准备界面显示当前步骤，详细记录保存在数据目录的
desktop-setup.log（环境准备日志）。后端就绪检查的 90 秒从环境准备完成后开始计算。

安装版和完整压缩包默认把配置放在 YAB.exe（桌面入口）旁的 config（配置目录）中：

- profiles（任务配置目录）：各账号的 config.json（配置）、event.json（调度）等文件。
- ocr（识别设置目录）：global_setting.json（识别服务设置）。
- webui.json（网页服务设置）：监听地址和端口，适用于所有任务配置。

首次使用这一布局时，会复制已有桌面版配置，原目录保留；目标位置已有配置时使用本地配置。
备份或搬到另一台电脑时，复制整个 config（配置目录）即可保留任务和识别设置。
配置位置可由 YAB_CONFIG_DIR（配置位置环境变量）覆盖；安装目录不可写时会明确提示，
可改选当前用户可写的安装目录或设置该变量。

运行环境、日志、浏览器状态和回退备份继续保存在当前用户应用数据下的 yab-desktop（桌面数据目录），
可由 BAAS_DESKTOP_DATA（运行数据位置环境变量）指定，不自动使用原 BAAS 的数据目录。
仅以源码目录启动时仍使用源码目录原来的配置布局。

## 更新与失败恢复

下载新版安装包覆盖安装，或关闭程序后将新版完整压缩包解压到新的目录启动。
程序和环境分别按内容版本保存：只改源码时复用依赖，依赖或解释器变化时准备新的环境。
新版通过后端健康检查后才启用；准备或启动失败时，桌面窗口提示原因，并在有使用相同配置位置的上一版本时回退。
冒烟验证遇到新版失败会直接报错，避免将回退结果算作新版本验证成功。

用户配置与各版本程序分开保存，新版启动前也会备份配置，回退时恢复到同一配置目录。
安装器按构建时的程序文件清单清理旧程序，覆盖安装始终保留应用数据。
卸载时默认勾选“保留应用数据”，取消后才删除本安装目录的配置，以及当前用户默认应用数据目录中的
配置、日志、运行环境和备份。通过环境变量指定到其他位置的数据仍保留，不清理原 BAAS 的数据目录。
卸载结束后按打包目录清单从深到浅重试移除空子目录，再移除空的安装目录；保留了配置或用户自行放入的文件时，目录也会保留。
本程序的安装和卸载注册信息由打包器模板移除；系统维护的开始菜单备份记录不由卸载器直接修改。
静默卸载默认保留数据；显式传入 --delete-app-data（删除应用数据参数）才清理，升级过程不清理。
旧程序、配置备份、失败的准备目录和缓存均保留，方便排查及手动清理。
构建不会打入现有用户配置、访问密码、日志或识别程序的仓库元数据；识别程序随发行包更新。
当前通过下载新版完整包或轻量包覆盖更新，尚未接入在线自动更新服务，网页中的旧启动器更新设置不适用于此发行方式。

这里参考了 SRC（星铁助手）将代码与依赖分别检查的方式，以及
[zzz-od（一条龙）的独立解释器、虚拟环境和本地依赖包](https://github.com/OneDragon-Anything/ZenlessZoneZero-OneDragon/blob/main/src/one_dragon/envs/python_service.py)。
保留的 backend.spec（旧冻结构建脚本）不参与当前发行；历史构建需要显式安装 legacy-build（旧打包依赖组）。

BAAS_UV（构建工具位置环境变量）可指定本机环境管理工具的可执行文件；普通构建自动从系统路径查找。

[MXU（Maa 新界面）的更新服务](https://github.com/MaaXYZ/MXU/blob/main/src/services/updateService.ts)
采用另一套渠道：通过 Mirror酱查询版本，有 CDK（下载凭证）时使用返回的下载地址，
否则查找 GitHub Release（平台发行页）中对应版本和平台的资产。下载后会备份配置，
再根据 changes.json（变更清单）选择增量或整包替换，并提供失败恢复。
这部分是渠道与包格式的参考，当前桌面发行尚未接入该服务。

桌面窗口默认只监听本机。需要局域网访问时，可在网页访问设置中修改监听地址，先设置访问
密码再重启应用；目前是共享密码控制，登录后可修改配置、启动和停止任务。
